# backtest-validation-kit

백테스트를 믿기 전에 먼저 답해야 할 두 가지 질문을 위한 작은 도구 모음입니다.

1. **백테스트가 내가 생각하는 것을 시험하고 있는가?** (데이터, 그리고 실거래 코드와 연구 코드가 같은가)
2. **결과가 우연보다 나은가?** (무작위 진입, 가격 순서 섞기, 거래를 무작위로 빼기, 과적합)

[English README](README.md)

## 왜 만들었나

규칙 기반 트레이딩 봇으로 제 돈을 걸고 실계좌를 3년 동안 운용했습니다. 2026년에 그 규칙을 더 긴 과거와 더 많은 종목에 옮겨 처음부터 다시 시험했습니다. 제가 했던 '개선'은 대부분 진짜가 아니었고, 데이터 오류 하나가 결과를 조용히 바꾸고 있었습니다. 아래 교훈 하나가 도구 하나가 됐습니다.

| 교훈 | 도구 |
|---|---|
| 데이터는 오류 없이도 틀릴 수 있다. 4시간 단위 가격 파일의 오래된 구간에 하루 단위 데이터가 섞여 있었는데, 코드는 잘 돌았다. | `data_check` |
| 비용까지 치르면 평균 거래가 손실인 전략에서는 무엇을 빼든 적게 거래할수록 덜 잃는다. 거래만 줄여도 필터가 똑똑해 보일 수 있다. | `trade_removal` |
| 여러 변형 중 1등을 고르면, 운만으로도 1등이 좋아 보인다. | `random_entry`, `shuffle`, `overfit` |
| 봇은 오류 하나 없이 백테스트와 다르게 매매할 수 있다. | `reconcile` |
| 이익이 난 기간도 몇 건의 거래에 기대고 있을 수 있고, 평균이 양수여도 운일 수 있다. | `bootstrap`, `concentration` |

이 레포에는 **방법만** 처음부터 다시 써서 담았습니다. 원본 연구 스크립트는 실계좌 자료와 실제 규칙이 섞여 있어 공개하지 않습니다. 실제 전략 값과 브로커 데이터는 없습니다. 예제 1 ~ 5는 합성 가격으로, 예제 6은 실제 공개 시세로 돌아갑니다.

## 도구

| 모듈 | 질문 | 방법 | 결과 |
|---|---|---|---|
| `data_check` | 가격 데이터가 파일 이름대로인가? | 달마다 봉 간격의 중앙값을 기대한 시간 단위와 비교(4시간 파일 속 일봉 등), 빈 구간, 있을 수 없는 가격(0 이하, 고가가 시가 · 종가보다 낮음, 저가가 높음), 홀로 튀는 값 | 기간별 문제 표 |
| `random_entry` | 진입 타이밍이 뭔가를 더하는가? | 종목마다 거래 수, 거래마다 방향 · 크기 · 비용 · 보유 기간은 그대로, 진입 봉만 N번 무작위(기본 1,000) | p = 샤프가 전략 이상인 무작위 비율 |
| `shuffle` | 가격 패턴을 쓰는가, 그냥 상승 덕인가? | 봉을 통째로 섞어 움직임은 같고 순서는 없는 가짜 가격을 만든 뒤 같은 전략을 돌림 | p = 가짜 가격에서 전략이 실제 이상인 비율 |
| `trade_removal` | 필터가 좋은 거래를 고르는가, 거래를 줄일 뿐인가? | 같은 수의 거래를 무작위로 N번 뺀 결과와 비교 | p, 그리고 개선을 '덜 거래한 몫'과 '고른 몫'으로 나눈 값 |
| `overfit` | 여러 번 시도한 뒤에도 1등이 의미 있는가? | PBO(조합 대칭 교차 검증으로 잰 백테스트 과적합 확률), 보정 샤프(Bailey · López de Prado, 2014) | PBO(0.5 = 동전), DSR(진짜 샤프가 0보다 클 확률) |
| `reconcile` | 실거래 코드가 백테스트와 같은 거래를 내는가? | 두 거래 목록을 종목 · 방향 · 허용 오차 안의 가장 가까운 진입 시점으로 짝지은 뒤, 진입 시점 · 진입가 · 손절을 비교 | 일치율과 어긋난 거래 전부의 표 |
| `bootstrap` | 평균 거래가 0일 수 있나? | 거래를 복원 추출로 N번(기본 1만 번) 다시 뽑고, 평균의 t 통계도 낸다 | p = 다시 뽑은 평균이 0 이하인 비율 |
| `concentration` | 결과가 몇 건의 거래에 얼마나 기대나? | 가장 좋은 거래 1, 3, 5 …건을 뺀다 | 남은 합계의 비율, 합계를 0으로 만드는 데 필요한 상위 거래 수 |

보조: `core`(거래 목록 형식, 종가 기준 평가 수익, 샤프), `synth`(합성 가격, 일부러 망가뜨린 파일, 잘못된 틱). `examples/`의 장난감 이동평균 전략이 시험할 거래 목록을 만듭니다.

### 거래 목록 형식

거래 하나에 한 줄입니다. `random_entry`와 `shuffle`은 실제 거래와 무작위 거래를 똑같이 봉 종가로 평가하므로, 둘의 차이는 타이밍뿐입니다.

| 열 | 뜻 |
|---|---|
| `symbol` | 종목 이름(종목이 하나면 없어도 됨) |
| `side` | +1 매수, −1 매도 |
| `entry_time`, `exit_time` | 봉 시각. 그 봉의 종가에 들어가고 나온다 |
| `size` | 자본 대비 노출(기본 1) |
| `cost` | 거래 하나의 비용, 자본 대비(기본 0) |
| `pnl` | `trade_removal`, `bootstrap`, `concentration`이 쓴다 |
| `entry_price`, `stop` | `reconcile`이 쓴다 |

## 예제가 보여 주는 것

예제 1 ~ 5는 합성 데이터, 예제 6은 실제 공개 시세이고, 난수 씨앗을 고정했습니다.

1. **`01_data_check`**: 2016년부터 4시간 단위처럼 보이는 파일에 2018년 말까지 일봉이 섞여 있고, 잘못된 틱이 하나 있습니다. 둘 다 찾아냅니다.
2. **`02_coin_flip`**: 장난감 전략이 추세 구간이 있는 시장에서 +24%를 냅니다. 무작위 진입 대비 p = 0.13, 섞은 가격 대비 p = 0.09이고, 설정 20개 중 1등이라 보정 샤프는 0.85입니다. 판정: 동전 던지기와 구분되지 않음.
3. **`03_filter_or_fewer`**: 우위가 없는 시장 20개에서 '2연패 뒤 한 번 쉬기' 필터가 결과를 좋게 만듭니다. 20개 모두에서 덜 거래한 몫이 개선을 만들고, '고른 몫'은 평균 +2%이며 운만으로 20개 중 3개에서 p < 0.05를 넘습니다.
4. **`04_pbo`**: 우위가 없는 시장 6개에서 PBO는 평균 0.52지만, 시장 하나씩 보면 0.32부터 0.80까지 흩어집니다.
5. **`05_reconcile`**: 일부러 심은 문제 네 가지(한 봉 늦은 진입, 다른 손절, 빠진 거래, 더 생긴 거래)를 모두 찾아냅니다.
6. **`06_real_prices`**: BTC · ETH 4시간 봉, 2020-01 ~ 2026-06, 매수만, 거래 한 번에 0.2%. `data_check`가 두 코인 모두 2020-03-12 20:00에 '튀는 값'을 하나씩 짚습니다. 이것은 데이터 오류가 아니라 실제 코로나 폭락입니다. 도구는 후보를 찾고, 판단은 사람이 합니다. 전략은 돈을 벌었고(거래 408건) 보정 샤프도 0.99지만, 두 코인을 그냥 들고 있는 쪽의 샤프가 더 높았습니다(0.87 대 0.72). 무작위 진입도 충분히 자주 그만큼 했고(p = 0.18), 섞은 가격도 마찬가지였습니다(BTC p = 0.07, ETH p = 0.36). 판정: 동전 던지기와 구분되지 않음.
7. **`07_luck_or_few_trades`**: 예제 2의 추세 시장에서 장난감 전략은 317건으로 +24%를 내지만, 부트스트랩으로는 평균이 0일 가능성을 배제하지 못하고(t = 0.71, p = 0.24), 가장 좋은 3건을 빼면 합계가 음수가 됩니다. 무작위 행보에서는 합계가 음수입니다(p = 0.88).

## 결과 읽는 법

- **돌리기 전에 통과 기준을 정합니다**(예: 모든 데이터에서 p < 0.05, DSR ≥ 0.95). 먼저 적어 두어야 시험이 정직해집니다.
- **모든 전략은 동전 던지기**라는 가정에서 시작합니다. 이 시험들은 그 가정을 기각할 수는 있어도, 우위를 증명하지는 못합니다.
- 무작위 진입 대비 p가 낮다는 것은 *이 데이터에서* 타이밍이 무작위보다 낫다는 뜻일 뿐, 미래를 말해 주지 않습니다.
- PBO가 0.5 가까우면 고르는 과정 자체가 과적합입니다. 고른 기간의 1등이 다른 기간에서는 아무거나 고른 것보다 낫지 않습니다.
- **돈을 번 것과 타이밍 실력은 다릅니다.** 보정 샤프가 높다는 것은 시도 횟수를 고려해도 수익이 0이 아닐 가능성이 크다는 뜻일 뿐, 진입 시점이 좋다는 뜻은 아닙니다. 예제 6은 DSR이 0.99인데도 같은 코인을 그냥 들고 있는 쪽이 더 나았습니다.
- **p값 하나, PBO 하나는 한 번 뽑은 값입니다.** 우위가 전혀 없는 시장에서도 시장 하나의 PBO는 0.32 ~ 0.80으로 흩어졌고(예제 4), 쓸모없는 필터가 20개 중 3개에서 p < 0.05를 넘었습니다(예제 3). 여러 데이터, 특히 규칙을 고를 때 보지 않은 데이터에서 함께 통과해야 합니다.

## 하지 않는 것

- 비용을 계산하지 않습니다. 커미션 · 스프레드 · 슬리피지 · 스왑은 거래 목록에 이미 들어 있어야 합니다. 제 시험에서는 스왑 하나가 비용 전 이익을 손실로 바꿨습니다.
- 백테스트 엔진이 아닙니다. 가격과, 직접 만든 거래 목록을 받습니다.
- 무작위 거래끼리는 겹칠 수 있고, 모든 거래를 봉 종가로 평가합니다. 봉 안에서 걸리는 손절은 다루지 않습니다.
- 예제는 도구가 어떻게 움직이는지 보여 줄 뿐, 어떤 전략이 통하는지는 보여 주지 않습니다. 예제 6도 기간 하나, 코인 두 개입니다.
